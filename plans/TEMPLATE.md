## Risks

One block per risk. Name them `Risk A`, `Risk B`, and so on, so they can be referred to
later. If there is genuinely no risk, write `No risks identified` and say why — an empty
section is not the same as a considered one.

Never invent a cost or a number. Where none is known, write `not measured`.

### Risk A — <short name>

| Question | Answer |
| --- | --- |
| **How bad?** | `HIGH` / `MEDIUM` / `LOW` |
| **What actually happens?** | The real-world impact if this lands, not the label. Who is hurt and how. |
| **Short or long term?** | `SHORT` — a one-off that passes. `LONG` — structural, it stays until something changes. |
| **Solution** | What we would do about it. `none yet` is an honest answer. |
| **What would the solution fix?** | Tick only what genuinely applies: operational load / manual work / automation / compliance. `none of these` is allowed and often true. |
| **Risk of the solution itself** | Every fix brings its own risk. What does this one bring? "None" is almost always wrong. |
| **Cost** | Time to build, money, and — the one people forget — ongoing upkeep. `not measured` if unknown. |
| **What we expect after** | What should be true once it is in place. This is what gets checked later. |
| **Does a human need training?** | `NO` — it works without anyone learning anything. `YES` — say who must learn what, because that is a hidden cost. |
